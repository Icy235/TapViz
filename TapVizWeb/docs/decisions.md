## ADR-001: стек первой итерации

**Решение.** Android остаётся в уже открытом проекте Kotlin/Compose по указанному выше пути. Web/API размещён в `D:\Projects\TapViz` на Node.js 24, встроенном HTTP-сервере и SQLite через `node:sqlite`; HTML рендерится сервером, интерактивный UI — небольшими локализованными ES-модулями. QR генерируется сервером в SVG.

**Причины.** Папка API/Web пуста, но пользовательский Android Studio проект найден в отдельном каталоге и сохранён без переписывания. Web/API монолит можно запускать независимо; Android получает стабильный контракт API.

**Компромиссы.** SQLite и синхронный драйвер годятся для локальной разработки и одного процесса, но не для горизонтального production-развёртывания. Перед production нужны PostgreSQL, проверенные миграции, SMTP/провайдер auth, централизованный rate limit и мониторинг.

## ADR-002: аккаунты и сессии

Пока нет выбранного провайдера, локальная регистрация использует scrypt из Node.js, случайный opaque-токен сессии и только SHA-256 его хеша в БД. Cookie — HttpOnly, SameSite=Lax, Secure в production. Вход/регистрация ограничиваются по частоте. Восстановление пароля требует подключённой почты и не имитируется.

## ADR-003: публичная ссылка

Публичный slug генерируется независимо от email и телефона и не меняется при редактировании карточки. Скрытие карточки немедленно прекращает публичную выдачу; повторное включение публикации возвращает тот же URL. Удаление аккаунта и связанной карточки — мягкое удаление с немедленным закрытием публичной страницы; окончательная очистка будет выполняться по настраиваемому сроку хранения.

## ADR-004: рынок, монетизация и локализация

- Основной язык первой версии — русский; ключи интерфейса выделены для добавления английского.
- Страна запуска, юридическое лицо, платёжная валюта/цены, провайдер платежей и OAuth-провайдер не заданы. Они остаются конфигурационными решениями; реальные реквизиты и цены не добавляются.
- Тарифные лимиты находятся на сервере. Начальный бесплатный лимит — одна опубликованная карточка. Продажи и покупка в первой итерации выключены.
- Правовые документы и согласия имеют технические места, но требуют проверки специалистом по выбранной юрисдикции до выпуска.

## Итерация 1 — результат

- Android: подключён отдельный Compose-клиент к `/v1`; есть регистрация/вход, редактор и темы, переключатели видимости, предпросмотр, QR, системный Share, системный экспорт PNG/VCF, настройки и состояние статистики с честно выключенным сбором. Cookie-сессия шифруется Android Keystore.
- Добавлены Compose Preview локальных состояний: авторизация, редактор, QR, профиль.
- Проверено: Node integration tests (2/2), JS syntax checks; Gradle `:app:assembleDebug` и `:app:testDebugUnitTest` успешны.
- Ограничения этой итерации: один профиль, нет восстановления пароля и подтверждения email, загрузки аватаров, сбор аналитики, экспорта/удаления аккаунта, юридических документов и PostgreSQL. Android не запускался на эмуляторе: подключённых устройств нет. Git-репозитории в обеих папках не обнаружены.

## Вертикальный сценарий и риски

Пользователь регистрируется → создаёт профиль → отмечает публичные каналы → публикует → делится коротким URL/QR → гость сохраняет VCF/открывает контактное действие → владелец скрывает профиль.

Открытые вопросы владельца продукта для выпуска: страна и юрисдикция, auth-провайдер/почта, домен публичных страниц, способ распространения Android и платёжный канал. До их решения реализация остаётся пригодной для локального dev и демонстрационного staging без реальных секретов.

## Итерация 2 — сайт TapViz и подготовка выкладки

- Пересобрана визуальная система Web: графитовый фон, электрический голубой акцент, крупная типографика и сдержанные свечения. Добавлен презентационный лендинг с отдельным входом/регистрацией, адаптивное рабочее пространство, обновлены QR экран и публичная SSR карточка.
- Анимации привязаны к задачам: вход содержимого, плавающая демонстрационная карточка, сканирующий блик, состояния наведения/нажатия, появление QR и профиля. В `styles.css` есть `prefers-reduced-motion`.
- Редактор поддерживает несколько карточек, настройку каналов связи, приватность и порядок, живой предпросмотр, три оформления и выбор фото. Фото пережимается браузером в PNG ≤ 512 px; сервер ограничивает размер, проверяет PNG структуру и размеры, а фото выдаётся публично только в уже публичной карточке.
- Лимит Free по умолчанию — три карточки; сервер отдаёт `/v1/plans`, ограничение задаётся `FREE_CARD_LIMIT`. Это конфигурируемое продуктово-тарифное допущение без цен и оплаты.
- Для данных SQLite добавлена совместимая миграция `avatar_data`. Docker Compose поднимает Node 24 одним процессом с постоянным volume; отдельный Nginx vhost проксирует только `tapviz.vorlan.ru`.
- Обновлены инструкции локального запуска и production deploy. Root-пароль/SSH-данные не попадают в файлы репозитория.
- Проверено: тесты API (2/2), `node --check` для сервера, браузерного JS и тестов; локально открыт новый лендинг. Визуальное дерево доступности подтверждает заголовки, действия и секции лендинга.
- DNS A-запись `tapviz.vorlan.ru → 31.76.78.227` теперь резолвится. На сервере предварительно обнаружены Ubuntu 26.04, Nginx, Docker Compose и Certbot Nginx plugin; `/opt/tapviz` свободен. Остальные домены и конфигурации не менялись.
- Требуют проверки перед полноценным публичным запуском: юридические тексты/юрисдикция, восстановление доступа и подтверждение email, off-host backup SQLite, политика аналитики, модерация и платежи. Одна серверная инстанция SQLite не горизонтально масштабируется.
